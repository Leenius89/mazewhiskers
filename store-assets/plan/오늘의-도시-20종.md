# 오늘의 도시 — 20종 기획

## 먼저, "20개가 한계"가 아닙니다

오늘의 도시는 **미리 만들어 둔 맵 20개를 하나씩 꺼내 쓰는 방식이 아닙니다.** 그날 날짜가 시드가
되고, 시드에서 도시를 그려 냅니다. 시드는 날마다 새로 생기므로 도시는 무한히 나옵니다.

여기서 말하는 20종은 **"어떤 종류의 도시인가"**입니다. 모양, 크기, 골목의 성격, 바닥 상태,
재개발 속도를 묶은 설계도이고, 하나의 설계도에서 매번 다른 도시가 나옵니다.

| | 개수 | 반복 주기 |
|---|---|---|
| 도시(미로 그 자체) | 무한 | 없음. 같은 도시는 두 번 나오지 않습니다 |
| 종류(설계도) | 20 | 20일마다 같은 *종류*가 돌아옵니다. 도시는 그때도 처음 보는 도시입니다 |

즉 20일 뒤에 돌아오는 것은 "그 맵"이 아니라 "원형 도시였던 날"입니다. 사용자가 많아도 닳지
않습니다. 20종을 다 쓰고 더 원하시면 종류를 늘리는 건 언제든 됩니다.

## 지금 미로 생성 방식과, 진짜 미로 알고리즘

지금 쓰는 방식은 이미 교과서에 있는 알고리즘입니다. **재귀 백트래커(깊이 우선 탐색)**로
완전미로를 판 다음, **브레이딩**으로 막다른 길 40%를 뚫어 순환로를 만들고, **광장** 몇 개를
비웁니다. "완전미로 + 브레이딩"은 추격이 있는 게임에서 표준으로 쓰는 조합입니다. 막다른 길만
있는 미로에서는 쫓기면 무조건 죽기 때문입니다.

다른 알고리즘으로 바꾸면 **게임 구조가 바뀌는 게 아니라 골목의 성격이 바뀝니다.** 게임의 나머지
부분(판정 상자, 아파트, 적의 길찾기, 미니맵)은 전부 **"0은 길, 1은 건물"인 격자 하나**만 읽기
때문에, 격자를 채우는 방법을 바꾸는 것은 안전합니다.

| 알고리즘 | 나오는 도시의 성격 | 비용 |
|---|---|---|
| 재귀 백트래커 (지금) | 길이 길고 구불구불함. 갈림길이 적음 | — |
| 프림 / 크러스칼 | 짧은 갈림길이 아주 많음. 방향 감각이 흐려짐 | 낮음 |
| 엘러 | 가로로 긴 직선 통로. 대로처럼 보임 | 낮음 |
| 재귀 분할 | 긴 직선 벽과 네모난 구획. 계획도시처럼 보임 | 낮음 |
| BSP 방 + 복도 | 방(공터)과 복도. 던전 생성에서 제일 흔한 방식 | 중간 |
| 셀룰러 오토마타 | 유기적인 덩어리. 판자촌·골목 밀집 지역 | 중간 |
| 드렁큰 워크 | 불규칙한 통로. 비계획 난개발 | 낮음 |

**원형·방사형 맵**은 조금 다릅니다. 진짜 극좌표 격자(가운데를 중심으로 한 원형 칸)로 가면 칸의
모양이 바뀌어서 판정·물리·미니맵을 전부 손봐야 합니다. 그래서 이 기획서는 전부 **지금의 정사각
격자 위에서** 만듭니다. 원 바깥을 건물로 채우면 원형 도시가 되고, 중앙으로 향하는 직선 통로를
먼저 뚫고 나머지를 미로로 채우면 방사형 도시가 됩니다. **보이는 모양은 원형·방사형이고, 아래에
깔린 격자는 그대로**입니다. 판정이 원작과 같아야 한다는 조건을 깨지 않는 유일한 방법입니다.

## 모든 종류가 지켜야 하는 것 (자동 테스트)

종류를 추가할 때마다 다음을 시드 1,500개씩 돌려 확인합니다. 지금 미로도 이 테스트를 통과하고
있습니다(`src/game/core/mazeGrid.test.ts`).

1. **집까지 걸어서 갈 수 있다.** 점프를 한 번도 쓰지 않고. 시작 시 주는 점프 1개는 여분입니다.
2. **길이가 적정 범위 안이다.** 너무 짧아 싱겁거나, 너무 길어 시간 기록이 무의미해지지 않게.
3. **같은 시드는 같은 도시를 만든다.** 기기와 관계없이.
4. **시작 지점과 집 주변은 특수 지형이 아니다.** 빙판 위에서 시작하지 않습니다.
5. **빙판이 있는 종류**: 빙판에서 미끄러져 도착하는 칸이 항상 존재한다(막힌 곳에 영원히 갇히지 않음).

### 예비 (원하시면 20종 중 하나와 교체)

- **안개 도시**: 이지 난이도에 나이트메어의 시야 제한만 적용(보라색·글리치 없이)
- **급속 재개발**: 아파트가 두 배 빨리, 두 배 크게 들어섬
- **월세 도시**: 월세 주기가 절반. 생선을 계속 먹어야 버팀
- **정전**: 가로등이 꺼져 시야가 좁아짐

## 무엇을 더 만들어야 하나

지금 생성기는 `mazeSize`와 `ice` 두 가지만 받습니다. 20종을 다 만들려면 설계도에 다음 항목이
필요합니다.

```
mask        도시의 윤곽 (사각/원/마름모/십자/도넛/직사각)
generator   골목을 채우는 방법 (백트래커/프림/재귀분할/블록/오토마타/나선/방사형)
size        한 변의 칸 수 (25 / 41 / 61)
braid       막다른 길을 뚫는 비율 (0 = 완전미로)
plazas      광장 수
ice         빙판 비율과 배치 방식 (구간 / 대로)
pressure    아파트 속도·크기 배수
fog         시야 제한 여부
```

전부 **생성 단계에서만** 쓰이는 값이라, 게임이 도는 동안의 규칙(판정, 아파트가 길을 끊지 않는
보장, 적의 행동, 점수 계산)은 한 줄도 바뀌지 않습니다.

## 만드는 순서 (제안)

| 단계 | 내용 | 종류 | 드는 일 |
|---|---|---|---|
| 1 | 다이얼만으로 되는 것 | 11, 12, 14, 15, 16 | 설계도 항목 추가 + 테스트 |
| 2 | 마스크 | 2, 3, 4, 5, 6 | 윤곽 함수 + 시작·집 위치 보정 + 테스트 |
| 3 | 새 생성기 | 7, 8, 13 | 방사형·재귀분할·나선 + 테스트 |
| 4 | 새 생성기 (어려운 쪽) | 9, 10 | 블록·오토마타. 도달 보장이 가장 까다로운 둘 | 
| 5 | 빙판 배치 | 20 | 대로 판별 후 그 위에만 결빙 |

1단계와 2단계까지만 해도 **종류가 11개**가 되어 열흘 넘게 겹치지 않습니다.

## 순서 섞기

날짜 해시로 고르면 우연히 이틀 뒤에 같은 종류가 나올 수 있습니다. 20종이 준비되면 **20일을 한
주기로 20종을 한 번씩** 돌리되, 주기마다 순서를 섞는 방식으로 바꾸는 것을 권합니다. 같은 종류가
한 주기 안에 두 번 나오지 않고, 주기가 바뀌면 순서가 달라집니다.
