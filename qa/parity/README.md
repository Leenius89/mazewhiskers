# 원작 대조 테스트

토스 빌드가 원작(`main`)과 **판정까지 똑같이** 동작하는지 확인하는 도구입니다.
`main`의 수정을 `git merge main`으로 가져온 뒤에 다시 돌리면 됩니다.

두 빌드에 같은 시드, 같은 키 입력을 넣고 30프레임마다 고양이 위치(소수점 둘째 자리),
체력, 적 위치, 아파트 수, 무작위 호출 횟수를 기록해서 비교합니다.

## 무엇을 고정하는가

같은 코드라도 그냥 두 번 돌리면 결과가 다릅니다. 이 도구가 막는 원인 네 가지입니다.

| 원인 | 고정 방법 |
|---|---|
| `Math.random` | 장면 생성 직전에 시드 고정 |
| 프레임 시계, `requestAnimationFrame` | 가짜 시계로 한 프레임씩 직접 진행 |
| `Date.now` — Phaser 트윈(점프 궤적)은 게임 시계가 아니라 벽시계로 움직임 | 가짜 시계에 묶음 |
| 로딩에 걸리는 프레임 수 — 고양이 숨쉬기 연출이 절대 시각을 써서 판정 상자가 1px 미만 달라짐 | 로딩 중 프레임은 시간 0으로 진행 |
| 미로 생성의 `sort(() => rng.frac() - 0.5)` — 엔진이 최적화 전후로 다른 순서를 냄 | 결정적인 정렬로 교체 (두 빌드 동일) |

마지막 항목은 원작 게임 자체의 문제입니다. 같은 `?seed=`로도 미로가 매번 같지 않습니다.

## 돌리는 법

1. `main`을 임시 폴더에 빌드합니다 (원본 폴더는 건드리지 않음).
   ```
   git worktree add <임시>/ref-main main
   ```
   `node_modules`는 이 폴더의 것을 연결하고 `react-scripts build`.
2. 이 폴더는 검증용으로 빌드합니다: `REACT_APP_TOSS_SIM=1` (`?debug=1`이 켜짐).
3. 서버 두 개:
   ```
   python serve.py <ref-main/build> 5301
   python serve.py <toss build 복사본> 5302
   ```
4. 브라우저(폰 크기)로 각각 열고 콘솔에서:
   ```
   // http://127.0.0.1:5301/?debug=1&seed=qa-city-1&qaDiff=easy
   __qa.run({ name: 'orig', seed: 1, frames: 5400 })
   // http://127.0.0.1:5302/?debug=1&seed=qa-city-1&qaDiff=easy
   __qa.run({ name: 'toss', seed: 1, frames: 5400 })
   ```
5. `python compare.py orig toss` → `samples same` 이면 통과.

같은 빌드를 두 번 돌려 `same`이 나오는지부터 확인하세요. 그래야 도구가 결정적인 상태입니다.
